Local cleanup (**Verified**): no `opentelemetry-demo` containers or labeled volumes remained, ports 8080 and 9090 were free, and a `node` process on port 3000 is unrelated (Grafana's compose port mapping has no fixed host port). The demo is pinned at `DEMO_VERSION=3.0.0`.

Remote-write (**Verified**): `samples_total` equalled `samples_in_total` (21,941 at first check); failed, retried, and pending were all 0; no 401 or 403 in the Prometheus log. Kibana showed about 40.9K documents with the earliest timestamp matching the end of the WAL replay.

Consequences of the restricted key (**Verified**): a GET on the base URL returns 403 and a GET on the write path returns 405. The old `_cat/indices` check cannot be used. Prometheus's own remote-write counters are available on `http://localhost:9090/metrics`; querying them through `/api/v1/query` returned nothing.

**Cleanup still owed:** the old key was hardcoded in `config/prometheus-config.yaml` and may be in git history. It belonged to the old project: delete that project or revoke the key.

## 3. Open items

**Script and narrative claims that need to change or be measured**

1. "I didn't change a single character" / "exact same syntax you'd write in Grafana" overstates it. The PromQL *expression* is unchanged, but the line on screen adds the ES|QL `PROMQL index=... name=(...)` command. Suggested framing: the expression is unchanged and ES|QL's PROMQL command runs it and returns columns.
2. The PROMQL command is documented as a preview feature (9.4). The curriculum promises a non-oversold picture, so the video should say "preview" somewhere. Its status on Serverless specifically was not found.
3. **Organic error "humps."** Scripts say errors appear every few minutes (~5 min on, ~5 min off). Observed so far: one hump in about 30 minutes. **Open:** measure interval and amplitude over a longer run before keeping this claim.
4. **Scene 5 numbers** (0.004 baseline, 0.04 to 0.06 spike, "roughly ten times", the script's "5x" and "5 to 10x") come from the old project. Payment's call rate here is about 0.10 to 0.15 per second, so a 25% failure rate would give roughly 0.025 to 0.04 errors per second (**Inferred**). Measure before narrating a multiple.
5. Injection timing: do not flip `paymentFailure` while a hump is still draining.
6. Scene 3 mismatch: the Prometheus query has no service filter (all series) while Kibana Query 1 filters to six services. Either add a `service_name=~"..."` selector to the Prometheus query or change the narration.
7. Time picker: the cheat sheet says pin a fixed window; the script says Last 30 minutes. A fixed window would break the live chart in Scene 5.
8. Script wording refers to a table-view toggle (Scenes 2 and 4) that may not exist in this Kibana version.

**Environment questions**

9. **Container and service counts.** *Resolved:* the two compose files define 25 services and all 25 run (`ps -a` showed none Exited). The "30 containers" figure in the docs is stale (cause unknown). Prometheus reports 18 services, not 19. **Still to do:** update the cheat sheet's "19 services" wording and the Scene 3 narration. Sizing figures that depend on 30 containers (Instruqt VM size, memory table, image-pull estimate) were left as is and should be re-checked.
10. **Compose flags.** *Resolved:* `compose.yaml` alone defines neither Prometheus nor Grafana, so `-f compose.yaml -f compose.observability.yaml` is required. The environment guide said otherwise; corrected in sections 1.2, 1.7, 1.8, the validation table, and the key-files tree. **The Instruqt setup script in the same guide still runs plain `docker compose up --detach` and would start without Prometheus or Grafana.** It needs the same fix.

**Decisions for the root chat**

11. **Remote-write endpoint.** Elastic's docs recommend the Managed Prometheus Remote Write endpoint for Serverless (key with `event:write` for the `apm` application; no URL-path routing). The direct endpoint used here still works. Whether the managed endpoint writes to the same data stream name was not confirmed. This affects Module 2's content.
12. **Prometheus-compatible query endpoints.** The PROMQL docs mention `query` and `query_range` endpoints. If usable from Grafana, they may allow a truly unmodified query (relevant to Module 3).
13. **Instruqt key pattern.** The Instruqt sections still assume an unrestricted key and hardcoded values; they need the restricted-key and template pattern.
