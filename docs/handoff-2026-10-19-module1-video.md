## What this project is

A training curriculum for enterprise Prometheus and Grafana operators migrating to the Elastic Stack. It is structured as two tracks:

- **Track 1** (current focus) — Metrics migration via Prometheus remote-write. Prometheus keeps running throughout. No commitment required.
- **Track 2** (planned) — Full cutover: traces, logs, decommission Prometheus.

The philosophy is confidence through parallel operation. The learner runs both systems side by side, builds confidence, and migrates at their own pace. This is not a rip-and-replace story.

## Validated queries

**Query 1 — Multi-service request rate (Scenes 2 and 3):**
```esql
PROMQL index=metrics-generic.prometheus-default
  request_rate=(sum by (service_name) (rate(traces_span_metrics_calls_total[5m])))
| WHERE service_name IN ("frontend", "checkout", "cart", "payment", "shipping", "recommendation")
```
Kibana settings: Last 30 minutes, chart view.
Expected: frontend ~14–17 req/s dominant, others flat below it.

**Query 2 — Peak rate per service ranked (Scene 4):**
```esql
PROMQL index=metrics-generic.prometheus-default
  request_rate=(sum by (service_name) (rate(traces_span_metrics_calls_total[5m])))
| WHERE service_name IN ("frontend", "checkout", "cart", "payment", "shipping", "recommendation")
| STATS max_rate = MAX(request_rate) BY service_name
| SORT max_rate DESC
```
Table view. Expected: 6 groups, frontend highest, payment lowest.

**Query 3 — Payment error rate (Scene 5):**
```esql
PROMQL index=metrics-generic.prometheus-default
  error_rate=(sum(rate(traces_span_metrics_calls_total{status_code="STATUS_CODE_ERROR", service_name="payment"}[5m])))
```
Chart view, Last 30 minutes.
Expected before flag: organic humps at ~0.004 req/s.
Expected after flag at 25%: spike to ~0.04–0.06 req/s (~10x baseline).

**Prometheus query (Scene 3):**
```promql
sum by (service_name) (rate(traces_span_metrics_calls_total[5m]))
```
Graph tab, 5m time range.

## Known issues and gotchas

**Prometheus OOM after extended running:**
Default memory limit was 200MB, now patched to 1024MB in `config/compose.observability.yaml`. Also added `--storage.tsdb.wal-compression` and `--storage.tsdb.retention.size=800MB` flags. If Prometheus exits with code 137, copy the patched config from the repo and recreate the container.

**macOS Docker Desktop bind mount:**
Editing `prometheus-config.yaml` on the host does not refresh inside the container. Always restart Prometheus after editing config files.

**Chart rendering in Kibana Discover:**
Adding a WHERE pipe after a PROMQL block that groups by multiple dimensions breaks chart rendering. Use label selectors inside PromQL curly braces instead. See Query 3 for the correct pattern.

**Prometheus rate window after restart:**
After any Prometheus restart, wait at least 15 minutes before recording. The `rate()` function needs a full window of data to produce stable results. The chart will show a visible ramp during this period.

**Grafana Demo Dashboard shows No data:**
Use the Spanmetrics Demo Dashboard instead for Scene 1. It is driven purely by Prometheus metrics and populates immediately after startup.

**DEMO_VERSION must be pinned:**
The `.env` file in the OTel demo sets `DEMO_VERSION=latest` by default. Change it to `3.0.0` before pulling images or the payment service will fail to start with a MODULE_NOT_FOUND error.
